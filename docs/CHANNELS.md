# 从遮挡到故障：统一研究模型

本页是新增研究的定义、结果与复现入口。旧四侧遮挡的精确枚举仍在
[FOUNDATION.md](FOUNDATION.md)；可计算结果由
[`foundation.channel_experiments`](../foundation/channel_experiments.py)生成到
[`channels.json`](../foundation/results/channels.json)。这里的“容量”指任意二进制图案的
最大字符数，不是人眼能自然认识的字符数，也不构成交通设备安全结论。

## 先把问题问准确

一次观察有三个独立维度：显示布局、允许的遮挡、未知故障。遮挡从指定的段集合中
删除信息；故障改变仍可见的段。默认遮挡位置已知，因此接收者知道哪里的信息缺失。
“位置未知”是另一个更困难的模型：没有遮挡位置提示，隐藏位置只看起来是暗的。

用户提出的“从下往上看，某些方向不会遮挡”在这里作为可选情境假设，而不是已经
验证的道路几何事实。支持不遮挡、左/右二选一、左/右/上三选一、四侧任选一侧、
左右同时、四侧同时。**任选一侧与同时遮住几侧是不同问题。**

每段是一个可独立控制的二进制发光单元。它不必等于封装上的一个 pin：公共端、
复用扫描、驱动 IC、连接器损坏可能同时影响多个段或多个字符。当前研究不模拟这些
电气连接，也不从一个静态帧诊断持久故障；后者需要连接关系或时间序列数据。

### 三种故障

| 模式 | 可见效果 | 默认预算 |
|---|---|---|
| stuck-off / 熄灭 | 1 → 0 | 至多 k 个 |
| stuck-on / 常亮 | 0 → 1 | 至多 k 个 |
| flip / 任意翻转 | 0 ↔ 1 | 至多 k 个 |

k 可以取 0、1、2。“至多”包含没有故障的情况，这很关键：用户不知道有没有坏段。
物理故障可以落在本就熄灭或已遮住的段上，但它不会增加观察集合；生成器直接枚举
有效可见变化，与枚举所有这些物理位置得到的观察集合完全相同，测试对此穷举核对。
这里没有把“随机”偷偷变成某个概率分布：结论保证预算内所有情况，平均误读率需要
另行给定故障概率、遮挡分布与字符先验。

### 两种成功标准

**检测：不发生静默替换。** 一个字符经过允许损坏后，不能看起来像另一个干净字符。
这可以让系统拒绝异常输入，却不保证恢复原字符。它也不能保证察觉每一次物理故障：
未亮段的断路、隐藏段损坏都可能完全不可见。

**纠正：唯一恢复原字符。** 不同字符的全部可能观察集合必须互不相交。见到一个结果，
只允许一个原字符解释它；找到零个候选表示模型或输入不匹配，多个候选表示无法保证。
这是数学唯一性，不代表第一次看到自定义字形的人能凭直觉读出来。

实现为显式观察集合，不把不对称故障错误地当成普通汉明距离：

```
O(x) = { (遮挡身份, 观测图案) : 所有允许遮挡与至多 k 个故障 }
纠正失败 ⇔ O(x) ∩ O(y) 非空
检测失败 ⇔ O(x) ∩ Clean(y) 或 Clean(x) ∩ O(y) 非空
```

遮挡身份未知时，从观察键中删除身份，允许不同遮挡之间形成冲突。每个冲突都保存
两个原图案、遮挡、坏段掩码和相同观测作为可重播见证。

## 七段显示的关键结果

下表除明确标注“方向未知”的行外，均是遮挡位置已知、预算“至多”的全部 128 个图案上的**精确最大值**。无故障时
检测和纠正退化成同一个无歧义问题。具体参考构造在 JSON 的 `capacity.patterns` 中。

| 情境 | 故障 | 检测容量 | 唯一纠正容量 |
|---|---|---:|---:|
| 不遮挡 | 无 | 128 | 128 |
| 左右任选一侧 | 无 | 32 | 32 |
| 四侧任选一侧 | 无 | 32 | 32 |
| 四侧任选一侧，方向未知 | 无 | 28 | 28 |
| 左右同时遮挡 | 无 | 8 | 8 |
| 左右任选一侧 | 至多 1 个熄灭 | 16 | 6 |
| 左右任选一侧 | 至多 1 个翻转 | 16 | 4 |
| 左右任选一侧 | 至多 2 个熄灭 | 11 | 2 |
| 左右任选一侧 | 至多 2 个翻转 | 4 | 2 |
| 四侧任选一侧 | 至多 1 个熄灭 | 9 | 6 |
| 四侧任选一侧 | 至多 1 个翻转 | 9 | 4 |
| 不遮挡 | 至多 1 个熄灭 | 64 | 18 |
| 不遮挡 | 至多 1 个翻转 | 64 | 16 |
| 不遮挡 | 至多 2 个翻转 | 16 | 2 |

这给出几个比“换一个优化字体”更有用的结论：

1. **放宽成仅左右遮挡，不会提高无歧义的理论容量。** 一个侧面已删除两段，剩五段，
   最多只有 32 种观测；达到 32 的构造仍存在。放宽可以减少具体字库的冲突、减少
   修改代价，但“最大能放多少字符”不一定变化。
2. **左右同时遮挡时，十进制已经不可能。** 只剩 a、d、g 三段，最多 8 个字符。
   增加算法或继续微调七段字形不能装下 10 个不同字符。
3. **左右任一遮挡叠加一个未知坏段，纠正十进制也不可能。** 熄灭模型最大 6 个，
   任意翻转最大 4 个；这些上限针对任意重画的字库，不只是标准字体。
4. **只要求不静默误读，比要求恢复原数字宽松很多。** 同样的左右遮挡加一个坏段，
   可以编码 16 个字符来做检测，却只能纠正 6 个或 4 个。
5. **恢复上、下两侧约束会改变故障检测结论。** 四侧任一遮挡加一个未知熄灭或翻转，
   检测容量从左右情境的 16 降到 9，完整十进制连“不静默替换”也无法保证。
6. **知道挡在哪边本身就是信息。** 四侧任一遮挡无故障时，方向已知容量是 32；
   若观测中没有遮挡身份且隐藏段只看起来是暗的，容量降到 28。

标准 0–9 与已有四翻转候选的每种情境核验也在 JSON 中。候选“消除了四侧遮挡冲突”，
不等于“也能应对未知坏段”。生成器针对每项新要求重新验证，绝不沿用旧结论。

## 与经典纠错码的联系

固定已知遮挡后，记两字形剩余图案为 u、v，令 A 为 u=1,v=0 的段数，B 为 u=0,v=1。

| 模型 | 两字形发生冲突的充要条件 |
|---|---|
| k 个任意翻转，检测 | A+B ≤ k |
| k 个任意翻转，纠正 | A+B ≤ 2k |
| k 个熄灭/常亮，检测 | (A=0 且 B≤k) 或 (B=0 且 A≤k) |
| k 个熄灭/常亮，纠正 | max(A,B) ≤ k |

每个允许遮挡都必须通过。未知遮挡时还有跨遮挡的比较，因此实现采用观察集合而不是
将这些固定遮挡公式直接套用。

“已知擦除 s 位 + 未知翻转 t 位”的经典充分条件是最小汉明距离 d > 2t+s；我们对指定
遮挡族计算实际剩余信息，因此可以比把遮挡任意化更精确。经典背景参考：
[MIT 6.451 讲义](https://ocw.mit.edu/courses/6-451-principles-of-digital-communication-ii-spring-2005/bb895c1dee9ce0b39d6846e0aa984981_MIT6_451S05_FullLecNotes.pdf)。
熄灭是只把 1 清零的非对称 Z-channel，参考
[Codes for the Z-channel](https://arxiv.org/abs/2105.01427)。这里不宣称这些编码理论是新发现。

## 扩展布局与一个建设性答案

布局必须说明“格子”是像素、顶点还是边，X 的交点是否将段拆开，否则段数没有唯一答案。

| 本次布局 | 独立发光段 | 精确定义 |
|---|---:|---|
| seven | 7 | 标准两格外框与中横线 |
| cell-x11 | 11 | 每个格子各放一个 X，完整斜线是一段，共增加四段 |
| split-x15 | 15 | 同上，但每根斜线在交点拆成两个可独立控制的半段，共增加八段 |
| pixels9 | 9 | 3×3 像素，每个像素是一位 |
| grid16 | 16 | 3×3 顶点的 12 条正交边，加四角各连中心的 4 条斜线 |

新增格内斜线处在边框内，理想“最外侧边”遮挡不删除它们；grid16 也只删除最外边对应
的正交边。它们与旧 `seg11_diagonals()` 不同：旧模型用整屏四角连中心，并将接触某侧
的斜线随那侧一起删除。两个模型都可以研究，但容量不能跨模型挪用。真实遮挡有厚度，
要用实际覆盖到的段集合替换 masks，不能假定内部斜线永远受保护。

**一个可验证的构造：轮廓与冗余分工。** 在 split-x15 中保留标准 0–F 的七段轮廓，
再用七根内部半斜线编码经典 [7,4,3] Hamming 码的 16 个码字。无论外框哪侧被遮，甚至
四侧同时被遮，这七根内部段仍可见；一个未知翻转最多改变其中一位，故仍能唯一恢复
16 个标签。未用的第八根半斜线保持熄灭。完整字库与所有验证结果位于 JSON 的
`constructions.protected-hex15`。

这说明增加硬件冗余可以突破七段容量障碍，也提供了参考答案。它**不是**“人脑自然看得
懂”的证明：叠加的斜线可能损害轮廓辨认。下一步应比较把冗余放在字形内部、字形旁边
独立校验区，以及利用倒计时时序上下文三种机制，再用真实识别数据选择。

## 字符集不只是数量

十进制 10、十六进制 16、不区分大小写字母数字 36、区分大小写 62、Base64 64，均可
与数学容量比较。“字符数超过上限”能证明不可能；“没有超过”只说明存在某些二进制
编码，不保证每个标签都有常见、好辨认的字形。

科学计数法同时涉及负号、E、数字、小数点、位置和语法。简单地把 10+3=13 当成单格
字库会忽略小数点常是独立灯位、可与数字同时点亮这一事实。应分离主字形与 dp 属性，
再做字符串级分析；本轮记录库存比较与这一模型边界，不声称已完成科学记数显示设计。

## 复现与证据边界

```bash
python tests/test_channels.py
python -m foundation.channel_experiments
# 完整复现仓库中 144 个精确容量（需要可选 OR-Tools）
uv run --no-project --python 3.14 --with ortools python -m foundation.channel_experiments --sat
```

观察集合与冲突核验是精确的。七段容量采用有限冲突图的最大独立集搜索，附完整构造；
超时返回下界、上界与 `bounded`，不伪装成精确值。可选 CP-SAT 用独立约束模型缩小界限。
当前提交的 144 个情境均已闭合为精确值。其中 8 条记录由 CP-SAT 闭合：无遮挡的单个
熄灭/常亮纠正（容量 18），以及未知方向四侧无故障的检测/纠正（容量 28，各故障类型
在 k=0 时是同一个问题，因此对应 6 条记录）。这些记录带有 `method: CP-SAT`，全局
`computation` 字段记录生成命令与求解预算。CP-SAT 是可重跑的独立整数约束模型；这里
不把静态见证集本身误称为最大值的形式化证明。

不带 `--sat` 的运行不需要任何依赖，可能重现其中 136 个精确值而给另外 8 个返回界限。
若它弱于当前权威结果，脚本会明确输出 `channels.partial.json`，保留 `channels.json`，
避免一次快速实验悄悄降低已验证结果的精度。`--output` 可显式指定实验文件。
大布局本轮提供几何、参考字形核验和建设性下界，**没有**穷举全部 2^15/2^16 图案来
宣称最优容量。JSON 的 `exact`/`bounded` 是每个具体结果的权威状态。

`tests/test_channels.py` 在三位小系统中遍历故障模式、预算、遮挡可知性与所有图案对，
以独立枚举物理坏段的方法核对观察集合、检测、纠正、冲突见证；另核验七段关键容量
及受保护 Hamming 构造。前端测试直接消费 `channels.json` 中的 144 个情境及参考字体
冲突数，并复核容量构造，避免网页解释与 Python 研究模型悄悄分叉。
